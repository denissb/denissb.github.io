# AGENTS.md

Guidance for AI coding agents working on this repository.

## Project overview

Personal website/blog/CV for Deniss Borisovs, built with **Lume v1.18.4**
(Deno static site generator) and deployed to **GitHub Pages** via GitHub
Actions.

- Runtime/package manager: **Deno 2.x**
- Site generator: Lume, pinned in `import_map.json`
- Templating: Nunjucks (`.njk`, `.tmpl.js`)
- Styling: plain CSS + PostCSS nesting
- Deployment branch: **`master`** (not `main`)
- Output directory: `_site/` (gitignored, generated)

## Commands

Run from the repository root.

```sh
# Build the site into _site/
deno task build

# Build with the production URL used by CI
deno task build --location=https://denissb.github.io/

# Start the live-reloading dev server on http://localhost:3000
deno task serve

# Include draft pages while serving
deno task build -d
```

### Known lockfile issue

`deno task build` may fail with:

```text
Integrity check failed for remote specifier ... https://esm.sh/jszip@3.7.1
```

The committed `deno.lock` is stale relative to current remote dependency
contents. For local work, bypass the lockfile without modifying it:

```sh
# Build
echo "import 'lume/cli.ts'" | deno run --unstable -A --no-lock -

# Build + serve
echo "import 'lume/cli.ts'" | deno run --unstable -A --no-lock - -s
```

`--reload` passes through to Lume rather than Deno, so `deno task build --reload`
does not fix this. Regenerating `deno.lock` is the durable fix, but do it only
when the task is specifically about dependencies, and review the lockfile diff.

There is **no test suite or lint task**. Validate changes by building and
inspecting `_site/`.

## Content conventions

### Blog posts

Add Markdown files under `posts/`. `posts/_data.yml` already applies
`type: posts` and `layout: layouts/post.njk`, so new posts only need:

```yaml
---
title: Post title
description: Short description
date: 2025-01-31
tags:
  - Deno
  - Lume
draft: false # optional; drafts are hidden unless built/served with -d
---
```

Posts are sorted by `date` descending. Tags, tag pages, feeds, archive pages,
and search entries are generated automatically from post frontmatter.

### Regular pages

Use a Markdown or `.njk` file with `layout` frontmatter. To add a page to the
site navigation:

```yaml
menu:
  visible: true
  title: Page name
  order: 3
```

Current menu slots: Home `0`, Blog `1`, CV `2`.

### CV

`cv.md` frontmatter is the source for the CV layout and the home-page skills
section. The home page (`index.njk`) duplicates the skills list, so update both
when skill levels change.

`_config.ts` listens for `/cv.md` updates and tries to generate
`assets/Deniss_Borisovs_CV.pdf` with Puppeteer against
`http://localhost:3000/cv/`. PDF generation therefore needs the dev server
running, can fail silently (errors are caught), and uses an old Puppeteer
version. After CV changes, verify the PDF was actually updated or regenerate it
manually.

### Dynamic pages

Files ending in `.tmpl.js` export page data/functions consumed by Lume:

- `archive.tmpl.js` generates paginated `/posts/` pages.
- `tag.tmpl.js` generates `/tags/<tag>/` pages.
- `feed.tmpl.js`, `search.tmpl.js` generate JSON outputs.
- `feed.xml.njk`, `sitemap.xml.njk`, etc. generate feed/SEO files.

Preserve their exported `url`, `layout`, and generator/function shape when
editing.

## Templates and styling

- Layouts live in `_includes/layouts/`; shared partials in
  `_includes/templates/`. Use existing `{% include "..." %}` paths relative to
  `_includes`.
- Templates use Lume's `search.pages()`, `url`, and `date` filters. Keep menu
  and tag URLs consistent with generated routes.
- CSS is imported from `styles.css` in order. Add new CSS files there and
  prefer the existing component/section naming. PostCSS nesting (`& p { ... }`)
  is supported.
- `js/vendor/searcher/searcher.js` is tracked but regenerated during builds by
  `gpm`; avoid hand-editing it unless you also change `_config.ts`.
- `_data/netlify_cms.js` controls the generated Netlify CMS admin under
  `_site/admin/`. Update it if new editable content fields/types are introduced.

## Build/deploy behavior

- `_config.ts` sets the canonical site URL, copies `img`, `assets`, and
  `snaptext`, applies PostCSS/Terser/date/highlight/base-path/slugify/resolve
  URL plugins, and generates Netlify CMS config.
- CI runs `deno task build --location=https://denissb.github.io/` and publishes
  `_site` to the `gh-pages` branch on every push to `master`.
- Do not change the deploy branch to `main` unless the workflow is updated too.
- Builds fetch remote dependencies and assets (Deno Land, esm.sh, jspm.dev,
  jsDelivr, Google Fonts); network access is required.

## Agent checklist

1. Run `git status --short` before and after changes.
2. Build with the lockfile workaround above when needed.
3. Inspect generated output for affected routes (e.g. `_site/index.html`,
   `_site/posts/.../index.html`, `_site/tags/...`, `_site/feed.xml`).
4. Confirm `git status` does not include `_site/` or unexpected changes to
   `deno.lock`, `js/vendor/`, or `assets/Deniss_Borisovs_CV.pdf`.
5. Format changed TypeScript/JavaScript/JSON with `deno fmt <paths>`; avoid
   mass-formatting Markdown or Nunjucks unless requested.
6. Keep changes focused. Do not upgrade Lume/Deno dependencies or regenerate the
   lockfile as a side effect of unrelated work.
